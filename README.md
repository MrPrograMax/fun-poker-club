# RIVER · Fun Poker Club

Веб-сервис для домашних покерных вечеров: настройки, рассадка и крупное тёмное табло. Сервер на **Go**, интерфейс на HTML/CSS/JavaScript без сборщика и npm-зависимостей.

## Запуск

Нужен Go 1.24 или новее.

```sh
go run .
```

Открыть http://localhost:8080. Go встраивает фронтенд в исполняемый файл через `embed`; отдельный фронтенд-сервер не требуется.

```sh
go build -o river-poker .
./river-poker
```

## Возможности

- Турнир и кэш; название игры, стек, SB/BB, бай-ин и 2–200 игроков.
- Структура из 12 уровней по умолчанию или автоподбор под желаемую длительность турнира. Расчёт учитывает стек, число игроков, стартовые блайнды, перерывы и ожидаемые ребаи / ре-энтри / аддоны. Уровни можно редактировать; доступно BB ante.
- Призовые места в процентах с проверкой суммы 100%; распределение целых рублей без потери остатка.
- Имена и необязательные ники, подсказки из прошлых игр, случайная рассадка между несколькими столами и отдельная схема каждого стола. Вместимость стола задаётся в настройках (2–10), число столов рассчитывается автоматически; например, 15 игроков при вместимости 10 распределяются как 8 + 7.
- Табло без списка уровней и верхней полосы этапов: настройки и рассадка доступны через компактное меню с шестерёнкой, структура редактируется до начала игры. Большой таймер, пауза, переключение уровней, текущие/следующие блайнды, полноэкранный режим и звуковой сигнал.
- Ребаи автоматически увеличивают призовой фонд. Выбывание определяет места; когда остаётся один игрок, игра завершается.
- Фиксированное и прогрессивное баунти (PKO): выбор выбившего, счётчик выбиваний, заработанные награды и текущая стоимость головы. Для PKO настраивается доля немедленной выплаты (по умолчанию 50%); остаток увеличивает голову выбившего. Победитель получает свою оставшуюся голову.
- Ре-энтри возвращает выбывшего со стартовым стеком и новой базовой головой. Пример: платёж 1 000 ₽ увеличивает общий банк на 1 000 ₽, 200 ₽ резервируются на голову, 800 ₽ добавляются на призовые места. Аддоны и ребаи полностью идут на призовые места, не меняя голову. Суммы и фишки аддона настраиваются.
- Отдельные счётчики ребаев, ре-энтри и аддонов; журнал последних 200 действий. Ре-энтри пересчитывает предварительные места и может возобновить завершённый турнир. При этом награда победителю за собственную голову возвращается в игру, ранее заработанные выбивания сохраняются.
- В кэше: фиксированные блайнды, время сессии, докупки, сумма выхода и прибыль/убыток каждого игрока. Последний выход должен закрыть оставшийся банк.
- Ребай, аддон и ре-энтри применяются одним нажатием, с кнопкой «Отменить» в уведомлении. Отмена последней операции также доступна над участниками и в журнале; сохраняется после обновления страницы. Отмена восстанавливает банк, головы, места и счётчики, но не откатывает таймер или выбранный уровень. После отмены выбывания, завершившего игру, таймер остаётся на паузе. В кэше окно ввода суммы сохраняется.
- Для фиксированного баунти табло показывает стоимость одной головы. Для PKO текущие индивидуальные награды доступны через кнопку «Игроки и баунти»; среднее и общий фонд баунти на табло не выводятся.
- Демо с вымышленными игроками. Средний стек не отображается.

## Автоподбор структуры

В настройках откройте «Структура турнира», укажите желаемое время в минутах (включая перерывы) и нажмите «Рассчитать». До сохранения это только предложение. Необязательно можно указать суммарное ожидаемое количество ребаев / ре-энтри и аддонов за весь турнир.

Расчёт берёт общий объём фишек и ориентируется на финальный BB около 1/20 этого объёма. Это эвристика для неглубокого хедз-апа, а не прогноз точного времени окончания. Начальные SB/BB сохраняются; последующие номиналы округляются к единице фишек, выведенной из начальных блайндов. Количество уровней выбирается как можно ближе к заданной длительности уровня, а минуты распределяются так, чтобы вместе с перерывами получилась желаемая длительность. После последнего уровня перерыв не добавляется. Для слишком резкого роста показана подсказка.

Сохранённый автоподбор пересчитывается при изменении параметров подготовки. Ручная правка уровней отключает автоподбор. При создании игры структура фиксируется и больше сама не изменяется; фактические докупки автоматически её не перестраивают. Перерывы, темп игры, анте и поведение игроков могут сдвинуть реальное окончание. По завершении структуры таймер останавливается, но учёт выбываний остаётся доступным.

## Хранение и ограничения MVP

Один сервер = одна текущая игра с несколькими столами, общими таймером и призовым фондом. Состояние и список игроков сохраняются в `data/state.json` атомарной заменой файла; данные не попадают в Git. Browser localStorage хранит локальную копию. Действия отправляются на сервер сразу, состояние работающего таймера — каждые 5 секунд. Локальная копия и ревизия помогают восстановить незавершённое сохранение при обновлении страницы. Таймер использует абсолютные сроки уровней, поэтому обновление страницы и ограничение фоновых вкладок не замедляют игру.

Одновременная запись из двух вкладок защищена номером ревизии: при конфликте вторая вкладка получает сообщение и должна обновить страницу. Совместное редактирование в реальном времени, аккаунты, архив турниров, разделение одного выбивания между несколькими победителями, пересадка и объединение столов по ходу игры пока не реализованы. Начальная рассадка фиксируется при создании игры и сохраняется при выбываниях и ре-энтри. Деньги сервис не принимает и не переводит — только ведёт учёт.

Если открыть статическую папку `dist` через HTTP-сервер без Go API, приложение работает в локальном браузерном режиме. Данные такого просмотра не синхронизируются с Go-сервером.

Сервер по умолчанию слушает только `127.0.0.1:8080`. Для доступа из домашней сети:

```sh
LISTEN_ADDR=0.0.0.0:8080 DATA_DIR=./data go run .
```

Это прототип без авторизации. Перед размещением в интернете нужны авторизация, HTTPS и резервное копирование данных. Для просмотра табло на телевизоре проще подключить экран к компьютеру ведущего.

## Docker

```sh
docker build -t river-poker .
docker run --rm -p 127.0.0.1:8080:8080 -v river-poker-data:/data river-poker
```

## Проверки

```sh
go test -race ./...
go vet ./...
node --test tests/*.test.mjs
node --check dist/app.js
```

Node.js 20+ нужен только для тестов клиентской логики. Go-тесты проверяют хранение, конфликты конкурентной записи, неправильные запросы и выдачу фронтенда. JS-тесты проверяют таймер, переходы через перерывы, восстановление, завершение турнира и распределение призовых.

## Структура

```text
main.go            HTTP-сервер, API и файловое хранилище
main_test.go       интеграционные тесты сервера
dist/index.html    оболочка интерфейса
dist/app.js        экраны, действия, сохранение состояния
dist/engine.js     таймер, структура и расчёты
dist/styles.css    адаптивный интерфейс
tests/             тесты игровой логики
```

`GET /api/health` — состояние сервиса. `GET /api/state` — `{revision, state}`. `PUT /api/state` — тот же формат с текущей ревизией; устаревшая ревизия возвращает HTTP 409. Размер запроса ограничен 1 МиБ. Это API одного доверенного ведущего, не платёжный API.

## Следующий этап

Отдельная панель ведущего на телефоне и табло только для просмотра. Изменения ре-энтри, аддонов и выбиваний должны приходить на табло сразу, а время и состояние игры — определяться Go-сервером. Эта синхронизация пока не реализована; управление участниками открывается кнопкой «Игроки и баунти» под табло.

# Разработка Until Morning

## Структура проекта

```text
cmd/
  until-morning/main.go    # Точка входа: флаги, окружение, сигналы остановки
internal/
  appdata/                # Постоянная папка данных и перенос старых сохранений
  server/                 # HTTP API, файловое хранение, архив и запуск сервера
    server.go             # Настройки запуска и сборка приложения
    http.go               # Маршруты, HTTP-обработчики и заголовки безопасности
    store.go              # Текущее состояние и атомарная запись JSON
    state.go              # Проверка формата входящего состояния
    archive.go            # Архивирование и чтение прошлых игр
    launch.go             # HTTP-сервер и открытие браузера
    *_test.go             # Go-тесты рядом с кодом
web/
  assets.go               # Встраивание интерфейса через go:embed
  static/                 # HTML, CSS и JavaScript без отдельной сборки
  tests/                  # Тесты игровой логики на Node.js
scripts/                  # Сборка релизов, smoke- и стресс-проверки
packaging/macos/           # Нативная оболочка .app, управляющая Go-процессом
docs/                     # Документация и отчёт о стресс-тестировании
.github/workflows/        # CI и публикация релизов
go.mod
package.json              # Команды для JS-тестов; npm install не требуется
Dockerfile
start.sh / start.command / start.cmd
```

`cmd/until-morning` только считывает параметры и запускает приложение. Серверный код закрыт для внешнего импорта каталогом `internal`. HTTP API и файловое хранилище остаются в одном небольшом пакете `server`: его детали не требуют публичных интерфейсов или отдельных слоёв.

Игровые правила и расчёт результатов находятся в `web/static/engine.js`, интерфейс — в `web/static/app.js`. Go проверяет формат сохраняемого состояния, защищает запись от конфликтов ревизий, хранит текущую игру и архив. Перенос расчётов на сервер и управление с нескольких устройств пока не реализованы.

`web/static` содержит исходники интерфейса, а не результат сборщика. Go включает их в исполняемый файл через `go:embed`; после изменения JS/CSS бинарник нужно пересобрать. Запускаторы из исходников делают это сами.

## Запуск и сборка

Нужен Go 1.24+. Все команды ниже выполняются из корня репозитория.

```sh
go run ./cmd/until-morning
go build -o until-morning ./cmd/until-morning
```

Windows: `go build -o until-morning.exe ./cmd/until-morning`.

Браузер открывается по умолчанию после привязки серверного порта. `-open-browser=false` отключает открытие, в том числе для CI и Docker. Флаг `-data-dir` переопределяет `DATA_DIR`. В консоли выводятся адрес и фактический путь сохранений.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `LISTEN_ADDR` | `127.0.0.1:8080` | Адрес HTTP-сервера |
| `DATA_DIR` | Папка данных пользователя | Явный каталог сохранений; относительный путь считается от рабочей директории |

Запускаторы `start.*` сначала переходят в свою папку и, если `DATA_DIR` не задан, выставляют абсолютный путь к соседней `data`. Это сохраняет переносной режим старых ZIP-архивов. Прямой запуск и `go run` используют постоянную папку пользователя.

## Сохранения

База данных не требуется. `state.json` содержит текущую игру, библиотеку участников и доступные отмены; `archives/<game-id>.json` — прошлые игры с результатами и событиями. Формат файлов не изменился.

При прямом запуске корневой каталог данных:

| Система | Каталог |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Until Morning` (обычно `C:\Users\имя\AppData\Local\Until Morning`) |
| macOS | `~/Library/Application Support/Until Morning` |
| Linux | `$XDG_DATA_HOME/until-morning`; если переменная не задана абсолютным путём — `~/.local/share/until-morning` |

Если постоянного каталога ещё нет, программа копирует старую `data` рядом с бинарником (или рядом с `.app`, если она там есть). Копируется вся папка вместе с архивом, исходник остаётся на месте. Сначала готовится временная копия, затем она переименовывается целиком: ошибка копирования останавливает запуск, не оставляя частично перенесённую игру. Уже существующий каталог, даже пустой, автоматически не заменяется и не объединяется.

При переходе с ZIP на macOS закройте приложение и старый сервер, откройте папку выше через Finder → «Переход к папке» и скопируйте туда **содержимое** старой `data` (`state.json` и `archives`). Если в целевой папке уже есть игры, сначала сохраните обе папки отдельно: автоматического объединения нет. В запущенном macOS-приложении папка доступна через меню Until Morning → «Открыть папку сохранений».

Папки `data`, `.local` и `build` не входят в Git и Docker-контекст. Перед переносом сохраняйте резервную копию всей папки данных. Для экспериментов и ручных тестов задавайте отдельный `DATA_DIR`, чтобы не менять настоящую игру.

## Проверки

Для тестов интерфейса нужен Node.js 22+, для Go-тестов — Go. Сторонние npm-пакеты не используются.

```sh
go test -race ./...
go vet ./...
npm test
npm run check
sh -n start.sh start.command
```

Стресс-проверки:

```sh
npm run test:monkey -- --seeds 100 --steps 300 --seed 1
npm run test:monkey -- --mode cash --seeds 100 --steps 500 --seed 20261109
npm run test:api-stress
```

HTTP-прогон запускает отдельный сервер на свободном loopback-порту с временным хранилищем. Методика и результаты — в отчётах за [8 ноября](stress-test-2026-11-08.md) и [9 ноября](stress-test-2026-11-09.md).

## Готовые сборки

Для упаковки релизов дополнительно нужен Python 3. Файлы создаются в `build/releases/<version>/`: прямые `.exe` для Windows, `.run` для Linux и переносные ZIP для всех платформ. ZIP включает бинарник, запускаторы и инструкцию. Сохранения игр в сборки не добавляются.

```sh
python3 scripts/build-release.py v1.0.0
```

По умолчанию собираются Windows, macOS и Linux для amd64/arm64. Для одной платформы добавьте, например, `--target macos-arm64`.

Универсальный macOS `.pkg` собирается **на macOS с Xcode command-line tools**, после создания обоих macOS ZIP:

```sh
python3 scripts/build-macos-package.py v1.0.0
```

Установщик размещает `Until Morning.app` в `/Applications`. Оболочка на Swift/AppKit запускает Go-сервер, открывает его табло повторным нажатием на иконку и завершает сервер при выходе. И оболочка, и Go-сервер универсальные (arm64 + x86_64), минимум macOS 11. Приложение имеет локальную ad-hoc подпись для целостности, **без** сертификата Developer ID и notarization; PKG не подписан доверенным издателем. Это не снимает предупреждение Gatekeeper.

Smoke-проверки запускаются на соответствующей ОС и архитектуре, используют временные данные и подменяют только открыватель браузера. PKG извлекается без установки в системные «Программы»:

```sh
python3 scripts/smoke-release.py build/releases/v1.0.0/until-morning-v1.0.0-macos-arm64.zip
python3 scripts/smoke-desktop.py build/releases/v1.0.0/until-morning-v1.0.0-macos-universal.pkg
# На Windows / Linux:
python scripts/smoke-desktop.py build/releases/v1.0.0/until-morning-v1.0.0-windows-amd64.exe
python3 scripts/smoke-desktop.py build/releases/v1.0.0/until-morning-v1.0.0-linux-amd64.run
```

CI запускает проверки, кросс-сборку и Linux smoke на Ubuntu, сборку и smoke PKG на macOS, прямой EXE smoke на Windows. Публикация выполняется только при отправке тега `v*` после успеха всех трёх ОС. В Assets — 5 прямых загрузок и 6 переносных ZIP; SHA-256 отображается самим GitHub. Внутренний `SHA256SUMS.txt` сохраняется в артефакте сборки. Текст релиза берётся из `docs/release-notes.md`.

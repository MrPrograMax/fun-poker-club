# Стресс-проверка Until Morning · 8 ноября 2026

Проверялась локальная рабочая версия, включая освобождение мест после выбывания, поворот схемы и новый архив. Все операции выполнялись с вымышленными участниками в отдельных хранилищах. Сохранение основного сервиса на 8083 не использовалось для тестов.

## Результаты

| Проверка | Объём | Результат |
| --- | --- | --- |
| Случайные последовательности игрового движка | 100 воспроизводимых сценариев по 300 операций, до 200 игроков | 30 000 операций без нарушения проверяемых инвариантов |
| Интерфейс в браузере | 240 случайных действий в основном прогоне: ввод, выбор, подтверждение, отмена, управление игроками и таймером | Нет ошибок JavaScript; сохранение корректно загрузилось после reload |
| HTTP и файловое сохранение | 1 625 запросов; до 16 параллельных клиентов | Нет неожиданных статусов; при конфликте ревизий ровно один победитель |
| Архив под нагрузкой | 40 игр, по 300 событий в каждой | Содержимое совпало с отправленным, все игры доступны в списке |
| Автотесты JS | 115 тестов | Пройдены |
| Go | Тесты с race detector и go vet | Пройдены |

В последнем HTTP-прогоне p50 составил 1 мс, p95 — 7 мс, максимум — 42 мс. Это локальный короткий тест на одном компьютере, а не оценка пропускной способности публичного сервиса.

Проверялись сохранение общей суммы взносов, призов и баунти; отсутствие двух активных игроков на одном месте; уникальность участников; освобождение стульев; счётчики входов и аддонов; порядок выбывания; места; корректность часов; отмена действий и повторная загрузка. Начальные seed — 1–100; последовательности можно повторить.

## Найдено и исправлено

Сервер проверял наличие полей состояния, но не их тип. Например, `seats: null` и `game: 17` принимались с HTTP 200 и сохранялись. Это могло сделать сохранение непригодным для интерфейса. Добавлена проверка контейнеров настроек, участников, библиотеки и игры. Те же 20 некорректных вариантов теперь отклоняются с HTTP 400, не меняя сохранение. Проверка намеренно не дублирует всю бизнес-валидацию фронтенда.

## Дополнительно проверен архив

- Завершение турнира создаёт одну запись матча.
- Отмена завершения обновляет эту запись, а не создаёт дубликат со старыми выплатами.
- При создании новой игры предыдущая сохраняется, даже если не была завершена.
- Архив доступен после перезапуска и открывается только для просмотра: он не меняет текущую игру и не даёт отменять её действия.
- Старые сохранения получают ID без двойного архива при миграции.
- Недоступная папка архива не позволяет серверу отбросить предыдущую игру.
- Журнал новых игр больше не обрезается до 200 событий. Проверен матч с 450 событиями. Лимит HTTP-сохранения поднят до 8 MiB; бюджет снимков отмены остаётся 900 KiB.

## Повторный запуск

Нужны Node.js 22+ и Go 1.24+.

```sh
npm test
npm run check
go test -race ./...
go vet ./...
npm run test:monkey -- --seeds 100 --steps 300 --seed 1
npm run test:api-stress
```

`test:monkey` сохраняет отчёт в `.local/monkey-report.json`, а при сбое — seed, последовательность действий и тестовое состояние. `test:api-stress` сам запускает сервер на свободном loopback-порту с временным DATA_DIR, затем останавливает его; отчёт — `.local/api-monkey-report.json`. Он не обращается к рабочему серверу 8083.

Браузерный прогон выполнялся отдельным UI-контроллером, его случайные шаги сохранены локально в `.local/ui-monkey-trace.json`. Команды npm его не повторяют. Финальные проверки архива в браузере выполнялись дополнительно вручную через контроллер.
